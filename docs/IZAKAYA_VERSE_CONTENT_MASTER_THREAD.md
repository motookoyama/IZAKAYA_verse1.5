# IZAKAYA verse コンテンツ総合スレ

## 0. この文書の役割

この文書は、`IZAKAYA verse` におけるコンテンツ構築とプロジェクト整備を一体で進めるための基幹スレッドである。

- 目的1: 散在している世界観・リージョン・カード・UI 改修の論点を一本化する
- 目的2: コンテンツ制作と実装作業を同じ優先順位表で扱えるようにする
- 目的3: AI と人間が同じ「公開順」「整備順」「保守方針」で判断できる状態を作る

## 1. 現在の前提

### 起点プロジェクト

- 母体プロジェクトはオンライン ChatGPT プラットフォーム側に存在する
- このリポジトリは、その母体から派生したローカル実装・公開整備拠点として扱う
- 方針更新、世界観更新、構想整理は最終的に母体側へ集約し、ここは反映先とする

### 運用ラベル

- 物理リポジトリ名: `IZAKAYA_verse1.5`
- 現行運用ラベル: `IZAKAYA 1.6`
- 開発 URL: `http://localhost:1398/`

### 中核ディレクトリ

- `src/data/regions/`: リージョン定義 JSON 群
- `src/data/v2cards/`: キャラクターカード群
- `src/pages/`: 公開導線となるページ群
- `docs/`: 公開手順、設計資料、総合方針
- `management/`: 進行管理、運用ルール、整備用ドキュメント

## 2. IZAKAYA verse の中核構造

### 2.1 作品の核

`IZAKAYA verse` は、単なるページ集合ではなく、以下を束ねた「公開可能な会話体験アーカイブ」として扱う。

1. リージョン
2. キャラクターカード
3. UI 導線
4. 世界観の説明文
5. 生成・更新運用

### 2.2 リージョン定義

リージョンとは、製作者の意図と設定、世界、シナリオ、キャラクター、視覚設定情報をまとめ、特定のAIプラットフォームに依存せず展開することを目的としたシステムである。

リージョンは、単なるページ、チャット部屋、画像集、キャラクターリストではない。ChatGPT、Claude、Gemini、SillyTavern、ローカルLLM、BFF、将来のIZAKAYA Verse運用のいずれでも、同じリージョン核を読み替えて展開できるようにするための体験単位である。

AIエージェントは、リージョンを扱う際に以下を同時に保持する。

- 製作者の意図
- 世界設定
- シナリオ導線
- キャラクターとV2カード
- 目録で採用された視覚設定
- AIプラットフォーム非依存の展開情報

### 2.3 主要公開リージョン

現時点で公開軸として扱うリージョンは、`src/data/regions_v3.ts` の方針に基づき以下の 5 本とする。

1. `mtuber_region`
   メタチューバー。公開導線と演出の中核。
2. `iz_help_nexus`
   ヘルプ。案内、FAQ、運用ガイドの起点。
3. `yoidore_region`
   よいどれ。居酒屋性と物語体験の中核。
4. `ambient_region`
   アンビエント。空気感、背景、静的鑑賞の軸。
5. `mobility_region`
   モビリティ。技術性と未来感の公開軸。

この 5 本を「見せる導線」として優先し、それ以外のリージョンは拡張枠として整備する。

## 3. コンテンツ構築の柱

### 柱A: 世界観コンテンツ

- リージョンごとの説明文を短く強くする
- 各リージョンに「何を体験できる場所か」を一文で定義する
- 断片的な設定ではなく、公開時に読める導線へ落とし込む

### 柱B: キャラクターコンテンツ

- `src/data/v2cards/` を量産口として扱う
- カード JSON、サムネイル、表示用メタをセットで管理する
- キャラ追加時は「どのリージョンに紐づくか」まで決める

### 柱C: ページ導線コンテンツ

- Home: 世界観入口
- Region Select / Region Detail: リージョン回遊導線
- Library: キャラクター資産の陳列棚
- Chat: 体験の本体

ページは単独で整えるのではなく、どのコンテンツを見せる器かという観点で更新する。

### 柱D: 運用コンテンツ

- 更新ログ
- 公開順
- 作業優先度
- 品質基準

このレイヤーを軽視すると、素材が増えてもプロジェクトは整わない。

## 4. 優先整備対象

### 優先度S

1. 公開 5 リージョンの説明品質統一
2. Home から Region への導線明確化
3. Help Nexus に運用説明を集約
4. Library のカード資産整理

### 優先度A

1. 各リージョンの代表画像と代表文の固定
2. Region Detail の体験価値の言語化
3. Chat 側の文脈表示改善
4. リージョン追加時のテンプレート化

### 優先度B

1. 非公開リージョンの棚卸し
2. 旧名称と新名称の混在解消
3. アーカイブ資産の再配置

## 5. コンテンツ制作フロー

1. 企画する
   リージョンかカードかページかを先に決める。
2. 置き場を決める
   `regions` / `v2cards` / `pages` / `docs` / `management` のどこに属するかを確定する。
3. 公開導線を決める
   Home, Region, Library, Chat のどこから到達させるかを決める。
4. 最低限の表示品質を満たす
   タイトル、短い説明、画像、関連導線を揃える。
5. 運用ルールへ記録する
   この総合スレまたは `management/` 側へ追加する。

## 6. プロジェクト整備ルール

### 6.1 ファイル配置

- 世界観と方針は `docs/`
- 進行管理と運用ルールは `management/`
- 実データは `src/data/`
- UI は `src/pages/` と `src/components/`

### 6.2 命名

- リージョン ID は意味が通る英字スネークまたは既存規則に寄せる
- 表示名は日本語と英語の役割を分ける
- 公開名称と内部ファイル名のズレは文書に残す

### 6.3 公開判断

公開対象は以下を満たしたら通す。

1. 一文説明がある
2. 代表画像または代替視覚素材がある
3. 到達導線がある
4. 関連リージョンかカードへの接続がある
5. 破綻した導線や未実装ボタンを残していない

### 6.4 母体プロジェクトとの同期

今後はオンライン ChatGPT プラットフォーム上の母体プロジェクトを一次ソースとして扱う。

1. 大方針は母体側で定義する
2. ローカル repo では公開導線、UI、データ実装へ落とし込む
3. ローカルで発生した整理結果は、再度母体側へ戻せる粒度で文章化する
4. ローカル固有の暫定対応は「暫定」と明記し、母体仕様と混同しない

## 8. 完了条件

以下を満たした時点で、「総合スレが機能している」と判定する。

1. 公開中の主要リージョンが一覧化されている
2. 各リージョンの役割が文章化されている
3. カード追加の入口が明文化されている
4. UI ページの役割分担が固定されている
5. 次に何を整備するかが `management/` で追える

## 9. 直近メモ

- `region_master_source` は世界観の原典として別格扱いし、公開導線とは分離して管理する
- `3_reincarnation_judgment` のような強いテーマリージョンは、Showcase 5 本の後続拡張候補として扱う
- 既存作業ツリーには未整理の変更が多いため、今後の整備は「新規ドキュメント追加」から始め、段階的に UI とデータを同期させる
- 次回の統合作業では、オンライン ChatGPT 側の母体プロジェクトを読み直し、この文書を上位構想に合わせて再編集する

## 10. 2026-05-29 サービス再開へ向けた実行メモ

### 10.1 公開主線

1. リージョンサービスを可能な限り順次公開する。
   パブリック公開とステルス公開を分け、公開できるものから通す。
2. 連動プロモ活動を開始する。
   SNS のキャラクター投稿、QR 転生コード配布、短文紹介、代表画像を連動させる。
3. Xe コンテンツ登録へ進める。
   公開またはステルス公開済みリージョンから登録候補を選び、体験導線を整える。
4. 新作リージョンと新キャラクターカードを生産登録する。
   世界観を維持した V2 カードを作り、良いものは公式登録候補にする。
5. 上記の流れをもって、IZAKAYA verse の本格サービス再開を宣言する。

### 10.2 予備整備

- IZAKAYA 1.5 基本チャット bot サービスをブラッシュアップする
- ライブラリーの表示と編集を調整する
  画面が大きすぎる箇所は縮小し、確認と編集を続けやすい作業画面に寄せる。
- ブラッシュアップに伴うテストシミュレーションを行う
  公開導線、チャット導線、V2 カード導線、ライブラリー導線が詰まっていないか確認する。
- 旧 V2 カード体系の整理はリージョン公開作業とは別管理にする
  既存サービス登録を壊さないため、削除扱いのファイルは意図を確認してから扱う。

### 10.3 作業上の注意

- リージョン公開 push と V2 カード大規模移行を同じ単位に混ぜない
- 公式登録されたカードは、同一 ID なら上書き更新を基本とする
- ID が変わる場合は、ライブラリー、リージョン manifest、表示 UI の参照を同時に更新する
- 試験成果物と本採用成果物を混ぜない
