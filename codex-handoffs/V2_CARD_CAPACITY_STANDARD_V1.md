# 適正カード容量規格 V1

制定日: 2026-08-23
発行: IZAKAYA Verse 運営部
対象: 企画制作班、画像生成担当、V2カード登録担当、検証班
状態: **新規の公開候補V2カードから必須**

## 0. 目的

リージョンの世界設定・プロンプトを豊かにすることと、カード1枚を肥大化させることは別問題である。画像生成時の既定出力やBase64埋込みをそのままV2カードへ入れてはならない。

カードは「持ち出せる人格データ」、画像は「必要な時だけ読む配布素材」として分離する。容量管理はオーナーの確認作業ではなく、**企画制作班の完成責任**とする。

## 1. 必須規格

| 項目 | 標準 | 公開判定 |
| --- | --- | --- |
| V2本文JSON | 目安128KB、上限512KB | 上限超過はHOLD |
| `imageUrl` | 外部ファイルURLのみ | `data:` / Base64 は即HOLD |
| 公開用カード画像 | JPEGまたはWebP、長辺960px以下、300KB以下 | いずれか超過はHOLD |
| 一覧表示 | さらに軽いサムネイルを使う | 原画・V2本文を初期読込しない |
| 高解像度原画 | ローカル保管または明示的な別ダウンロード | 通常の公開V2 JSONへ入れない |

この規格は表現を削るためのものではない。人格、世界観、初回メッセージ、QR、プロンプト設計は維持し、重量の原因である画像の保存・配布方法だけを正す。

## 2. 制作順序

1. 企画制作班はテキストだけでV2カードの人格・世界設定・QR・初回メッセージを確定する。
2. 画像担当は公開用の軽量カード画像を別ファイルで生成・選定する。原画をカードJSONへ貼り込まない。
3. 登録担当は `imageUrl` に公開画像URLを設定する。
4. 公開候補にする前に、次の検査を実行する。

```sh
node tools/v2cards/check-card-capacity.mjs \
  --card src/data/v2cards/<カード名>.json \
  --image public/v2card-images/official/<画像名>.jpg
```

5. 検証班は結果を `PASS` / `HOLD` と容量値つきで記録する。検査未実行は完了ではない。

## 3. 例外と禁止

- 300KBまたは960pxを超える画像が演出上必要な場合、原画を別配布とし、公開カードには軽量版を使う。
- 例外的に公開カードへ重い画像を使うには、理由・実測値・代替案を添えたオーナーの明示承認が必要。
- 「AIが出力したまま」「見た目が良い」「以前からある」を超過理由にしてはならない。
- 既存のオーナー承認済み資産を、規格だけを理由に勝手に削除・置換しない。変換は個別承認で行う。

## 4. 公式8枚の先行適用結果

メタチューバー公式8枚は本規格の先行適用対象とした。

- Base64埋込み画像: 合計12.56MB → 軽量外部画像: 合計1.18MB（約90.6%削減）
- すべて700×960px、92〜258KB、本文JSON合計37KB
- プロンプト、人格、初回メッセージ、QR、設定値は `imageUrl` 以外不変として検証済み

変換証跡: `tools/v2cards/official-card-image-manifest.json`
公式8枚の回帰確認: `npm run test:v2-card-external-images`

## 5. 引渡し報告形式

```text
V2_CARD_CAPACITY_V1
- card: <カード名>
- json: <bytes>
- image: <format>, <width>x<height>, <bytes>
- imageUrl: external / no-data-uri
- prompt/QR/persona: unchanged or reviewed
- verdict: PASS / HOLD
- exception approval: none / <owner approval reference>
```

本規格は、リージョン容量配分（`IZAKAYA_VERSE_2_0_RELEASE_GATE_20260821.md` 第5-C節）のV2カード項目を、制作・検証用に具体化したものである。
